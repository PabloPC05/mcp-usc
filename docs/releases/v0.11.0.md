# mcp-usc 0.11.0 — horario personal y sesión HTTP reforzada

La v0.11 consolida el trabajo de horarios lectivos, amplía las lecturas disponibles con
`MoodleSession` y añade un perfil académico local. Todas las consultas normales siguen siendo HTTP:
REST, AJAX same-origin, formularios explícitos o GET públicos USC. El navegador se reserva al
inicio de sesión interactivo con Microsoft/MFA.

## Horarios y perfil académico

- `list_degree_timetables` descubre las páginas oficiales enlazadas por una titulación y sus centros.
- `get_degree_class_timetable` consulta curso, año, semestre, semana, grupos, materia y `program_id`.
- `get_my_class_timetable` usa un perfil local validado para no repetir titulación, curso, plan y
  grupos en cada consulta.

Los planes homónimos nunca se mezclan. Cada sesión conserva centro, `program_id`, URL de horario y
fuente. Cuando la USC no publica datos, el resultado lo declara expresamente; no sustituye el plan
por otro de nombre parecido.

## Campus mediante sesión HTTP

Cuando no existe token REST, `list_quizzes`, `list_course_contents`, `list_course_resources` y
`list_forums` pueden usar `core_courseformat_get_state`. Este fallback devuelve CMID y metadatos
limitados sin abrir páginas de actividades ni registrar visitas. No inventa IDs internos ni enlaces
descargables.

La detección de expiración reconoce redirecciones, errores de autenticación y páginas de login que
un proxy devuelva con HTTP 200, incluidas respuestas AJAX acotadas. Los diagnósticos de CLI no
incluyen cookie, `sesskey` ni cuerpo remoto y explican si hay que importar o renovar la sesión.
El proceso MCP también silencia el logging detallado del cliente HTTP para que las URLs AJAX con
`sesskey` y las cabeceras autenticadas no puedan aparecer en stderr.

## Finalización confirmada

Se añaden dos pares preview/ejecución:

- marcar o desmarcar la finalización manual de una actividad propia;
- marcar el criterio Moodle `SELF` de un curso como completado.

El preview comprueba identidad, curso, módulo, tipo de seguimiento y estado actuales. La ejecución
requiere un token de cinco minutos, ligado a esos parámetros y a la cuenta, y realiza una sola
mutación. Un timeout o respuesta inesperada se trata como resultado ambiguo y nunca se reintenta.

## Superficie y compatibilidad

La superficie pasa a 91 herramientas: 49 lecturas puras, 21 previews, 20 operaciones con efecto y
una inspección potencialmente stateful. Continúan disponibles cuatro recursos y cuatro prompts MCP.

La suite incluye el contrato común de sesión para Moodle 4.5, 5.0 y 5.2. Esto no certifica cualquier
plugin o instalación: cada función sigue dependiendo del servicio, permisos, fase y contexto que
Moodle exponga a la cuenta.

## Límites conservados

Los calendarios estructurados de examen solo se amplían cuando existe un vínculo verificable entre
titulación, plan, materia y calendario del centro. Feedback, Survey, Lesson, Workshop, Wiki,
Glossary y Database permanecen sin ejecutor contextual mientras sus esquemas, propietario o fase no
puedan demostrarse antes de una mutación. Tampoco se consultan correo, Teams ni Turnitin directamente.
